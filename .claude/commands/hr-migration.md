---
description: Generate, review and commit a Django migration safely
argument-hint: "[app label, or nothing to detect from the diff]"
---

Produce the migration for the model changes on this branch: $ARGUMENTS

A model change without its committed migration is a blocker in this repository — the staging boot
runs `migrate` and nothing on any server generates migrations.
[`docs/compliance/migrations-are-committed.md`](../../docs/compliance/migrations-are-committed.md).

Steps:

1. Work out which apps changed models: `git diff --name-only staging...HEAD` and look for
   `*/models.py`. If an app label was given, use it.
2. Generate:

   ```powershell
   python manage.py makemigrations <app_label>
   ```

3. **Read the generated file.** Report what it does, in plain language, for each operation:
   - a new column — is it nullable, or does it have a default? A non-nullable column without a
     default fails on a table with rows.
   - a removed or renamed column — what happens to the data in it?
   - a changed type — is the cast safe for existing values?
   - an index or constraint — on a table with how many rows? The staging box is small, and
     `migrate` runs before gunicorn binds, so this is downtime.
4. Rename the file if the autogenerated name is noise (`0014_auto_20261125_1032` →
   `0014_shiftswaprequest`). Keep the number.
5. Verify nothing is left:

   ```powershell
   python manage.py makemigrations --check --dry-run
   ```

6. Apply it locally and confirm the app still starts: `python manage.py migrate` then
   `python manage.py check`.

Rules:

- Never run `makemigrations` or `migrate` against a server.
- Never edit or delete a migration already applied on staging — add a new one.
- Do not reformat the file. `migrations/` is excluded from `black`, `isort`, `ruff` and the
  whitespace hooks deliberately.
- A data migration that touches employee or payroll rows is reversible, or its docstring says why
  it cannot be.
- If the change injects a field into an **upstream** model, it goes through `horilla/inherit/` so
  the migration lands in the extending app
  ([`docs/compliance/keep-the-fork-mergeable.md`](../../docs/compliance/keep-the-fork-mergeable.md)).

Finish by reporting what to put in the PR description: what the migration does to existing rows, and
roughly how long it will take on staging.
